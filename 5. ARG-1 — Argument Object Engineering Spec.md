# ARG-1 — Argument Object Engineering Spec

Sep 25, 2026 · @Ken Lee

## 1. Scope and normative sources

Deliverable: the `Argument` bounded context in `cdss-spine`: two persisted types (`GenericArgument`, `ActualArgument`), one transient type (`ActualArgumentDraft`, already shipped at 0.1.0), their invariants, storage, FHIR projection, register rendering contract, API, and conformance suite. Out of scope here: the evaluator pipeline internals (cluster 2), Deviation (CONTRACT-DEV-1, cluster 4), LinguisticVariable authoring (cluster 6).

**State of play.** Two artefacts already exist and disagree on the qualifier shape. Resolve by adopting the engine draft's five-signal qualifier as canonical and issuing CONTRACT-ARG-1 v2; do not carry both.

**Normative corpus text (verbatim statements).**

| ID | Statement |
| --- | --- |
| SPINE-1 | Every claim that crosses a face boundary (recommendation, alert, alert suppression, override acknowledgment, triage decision) is represented as an ActualArgument instantiating (or explicitly deviating from) a versioned GenericArgument. No component may release a bare score, label, or unexplained alert to any face. |
| SPINE-2 | The argument schema carries all six Toulmin elements; Qualifier and Rebuttal are mandatory, not optional. An argument without a stated qualifier or with an empty rebuttal slot that the corruption engine has findings for is invalid and MUST NOT be released. |
| SPINE-3 | One argument object renders in three registers (clinical, plain-language, compliance) from a shared ontology and controlled vocabulary. Renderers may compress or re-order; they MUST NOT add, remove, or reweight argument content per audience. |
| SPINE-4 | Fabric is append-only and tamper-evident (hash-chained). Bindings: recommendations as FHIR GuidanceResponse, lineage as Provenance, access as AuditEvent, conflicts as DetectedIssue, permissions as Consent, intake as QuestionnaireResponse. Corrections supersede, never edit. |
| SPINE-5 | Every argument pins guideline/GenericArgument version, terminology release, evidence-library snapshot, engine model version, engine configuration hash. Replayable bit-for-bit. |
| SPINE-9 | One read API with register-scoped projections; face caches are derived, disposable, rebuildable. |
| CS-3 | Argument View renders the Toulmin tree at criterion granularity: claim; grounds with encoding traces on demand; warrant with guideline citation and version; backing with evidence tier; qualifier and rebuttals per identity system; graded chips with cuts; evaluator stage trace on demand; all within one interaction. |
| OM-3 | Posterior, coverage, membership, reliability, fit are distinct non-coercible types from schema through transport to render. |

**Canonical element-to-supplier map (MAK-FFC Part 2).**

| Element | Supplied by |
| --- | --- |
| Claim | Deterministic evaluation of the argument tree; never an ML output directly |
| Grounds | Data-plane resources with provenance and capture context |
| Warrant | A GenericArgument node: guideline criterion, Bayesian likelihood structure, or ratified local rule; versioned |
| Backing | Tiered evidence-library entry behind the warrant (tier, source, currency) |
| Qualifier | Typed signals (five-signal registry); uncertainty is a schema element |
| Rebuttal | Corruption-engine findings, contraindications, DetectedIssue conflicts, unresolved guideline disagreements |

| Standard | Use here |

## 2. Data model

Three object types. `ActualArgumentDraft` (engine output, transient, 0.1.0 as shipped) is promoted to `ActualArgument` (persisted, append-only) only by the evaluator. Field names below are the 0.1.0 engine-draft names where they exist, so promotion is additive, not a rename.

### 2.1 GenericArgument (knowledge plane, versioned, ratified)

| Field | Type | Req | Notes |
| --- | --- | --- | --- |
| `object_type` | const `GenericArgument` | yes |  |
| `ga_id` | string, stable | yes | Identity across versions |
| `ga_version` | semver string | yes | Every ActualArgument pins it |
| `criterion_ids[]` | string, min 1, unique | yes | Ommatidial grain (OM-1): the criteria this node covers |
| `warrant_type` | enum `guideline-rule` \| `bayesian-likelihood` \| `ratified-local` \| `fuzzy-precondition` | yes | `local-rule` in 0.1.0 is folded into `ratified-local` |
| `warrant_content` | `{ref_kind: cql-elm-ref \| lr-structure-ref \| fml-rule-ref, ref: uri}` | yes | Pointer only; never restated clinical content |
| `backing_refs[]` | `{row_id, tier: E1\|E2\|E3}` | yes, min 1 | Evidence library rows |
| `release_thresholds` | `{threshold_set_ref: uri, ratified: bool}` | yes | Crisp thresholds live here, never in engine code (FS-8) |
| `envelope_ref` | Pin | yes | ApplicabilityEnvelope (MS-1); `unknown` is a legal envelope state, absence is not |
| `profile` | enum `default` \| `GPP` | yes | GPP ⇒ `warrant_type = guideline-rule` (GPP-9) |
| `lineage` | `{jurisdiction, guideline_system, supersedes[]}` | yes | SPINE-6 pluralism; siblings never merge |
| `commitments` | `{exclusions[], scope_conditions[]}` | yes | ME-3 ontological commitments |
| `ratification` | `{ratifier_id, authority, at, record_ref}` | yes | Who ratified this version |
| `content_hash` | sha256 | yes | Over canonical JSON of all fields above |

| `warrant` | `{ga_id, ga_version, warrant_type, applicability, content_ref, type_mapping_ref?}` | yes | As 0.1.0 |

## 3. Invariants

Each rule names where it is enforced: S = JSON Schema (wire), T = Rust type system (unrepresentable), E = evaluator runtime check, D = database constraint. A rule enforced at T is also emitted as S for non-Rust consumers.

| ID | Rule | Source | Enforced |
| --- | --- | --- | --- |
| R-01 | `ActualArgument` cannot be constructed without a `qualifier` containing at least one signal | SPINE-2 | T, S (`anyOf` over five arrays `minItems: 1`) |
| R-02 | `ActualArgument` cannot be constructed without `findings_evidence` | SPINE-2 | T, S |
| R-03 | If `findings_evidence.status = unavailable`, `evaluation.verdict` ≠ `released` | SPINE-2 | T (state type `Held`), E |
| R-04 | If `findings_evidence.applicable_confirmed_refs` is non-empty, `rebuttals[]` must contain one Defeater per ref with `source = corruption` | SPINE-2, AD-2 | E (set equality), S (`if/then minItems`) |
| R-05 | Any Defeater with `acknowledged_by = null` and `source = corruption` ⇒ `evaluation.verdict` ≠ `released` | AD-2 | E |
| R-06 | `warrant.ga_id@ga_version` must resolve to a ratified `GenericArgument` whose `content_hash` matches `binding.template.sha256` | SPINE-5 | E, D (FK on `(ga_id, ga_version)`) |
| R-07 | `binding.criteria[]` ⊆ `GenericArgument.criterion_ids[]` | OM-1 | E |
| R-08 | `claim.type` ∈ profile whitelist; profile `GPP` whitelist = {guideline-prompt, pathway-recommendation, reminder, information-summary, gather-more-information} | GPP-5 | T (enum per profile feature flag), S |
| R-09 | Profile `GPP` ⇒ `qualifier.posterior = []`, `qualifier.coverage = []`, `qualifier.membership = []`; `warrant_type = guideline-rule` | GPP-8, GPP-9 | T (fields absent from GPP build), S |
| R-10 | No arithmetic or comparison across signal types; no cast of any signal to number | OM-3 | T (newtypes, no `From`/`Into`), already tested in 0.1.0 C06 |
| R-11 | `backing[]` min 1 and every `backing[i].row` resolves in the pinned `library_snapshot` | Primer B | E, D |
| R-12 | `pins.template`, `pins.terminology`, `pins.library` must be `pinned`; `engine`, `model`, `configuration` may be `not_applicable` only when `warrant_type = guideline-rule` | SPINE-5 | T (per-warrant-type pin requirement), S (`if/then`) |
| R-13 | `prev_hash` equals `content_hash` of the previous ActualArgument in the same patient stream; genesis is null | SPINE-4 | D (trigger), E |
| R-14 | `content_hash = sha256(canonical_json(argument \ content_hash))`; canonical = RFC 8785 JCS | SPINE-4 | T (computed in constructor), D (check on insert) |
| R-15 | `supersedes` chain is acyclic and a superseded argument is never updated in place | SPINE-4 | D (no UPDATE grant on table; trigger rejects) |
| R-16 | `author.kind = evaluator`; no other principal may INSERT | SPINE-7, OM-5 | D (role grant), API (write endpoint bound to evaluator identity) |
| R-17 | `evaluation.gate_results` has exactly five entries in fixed order `[completeness, thresholds, envelope, conflicts, verdict]` | RG-1 | T (fixed-size array), S |
| R-18 | `evaluation.verdict = flagged` ⇒ `fit.status = observed` with at least one `Fit.status ∈ {out, unknown}` or a non-empty `unresolved-conflict` Defeater | ME-1, HA-4 | E |
| R-19 | `evaluation.verdict = released` ⇒ `fit.status = observed` and every `Fit.status = in`, or `evaluation.fit_judgment_ref` set | ME-1, MS-7 | E |
| R-20 | `GenericArgument` versions are immutable; a change is a new `ga_version` with `supersedes` in `lineage` | SPINE-5, CP-3 | D |
| R-21 | Every `grounds[i].resource_ref` must exist in the record at `created_at` and be readable under the argument's consent scope | SPINE-4 (Consent) | E |
| R-22 | Render output for any face contains the same content-set as the argument (no add, remove, reweight) | SPINE-3 | CI property test (§5, §9) |

Rust sketch of the state-typed constructor (illustrative shape only):

```rust
pub struct Draft;      // engine output, unverified
pub struct Held;       // evaluator verdict: held
pub struct Flagged;    // needs fit-judgment
pub struct Released;   // face-visible

pub struct ActualArgument<S> { /* fields per §2.2 */ _state: PhantomData<S> }

impl ActualArgument<Draft> {
    // Only path to Released: consumes the draft, requires qualifier + findings evidence by type
    pub fn evaluate(self, ev: &Evaluator, q: Qualifier, fe: FindingsEvidence)
        -> Verdict { /* Released | Held | Flagged */ }
}

pub enum Verdict { Released(ActualArgument<Released>), Held(ActualArgument<Held>), Flagged(ActualArgument<Flagged>) }

// Qualifier cannot be empty by construction
pub struct Qualifier(NonEmpty<Signal>);
pub enum Signal { Posterior(Posterior), Coverage(Coverage), Membership(Membership), Reliability(Reliability), Fit(Fit) }
// No From/Into between signal newtypes; no Deref to f64
```

## 4. Spine storage

### 4.1 Relational tables (Postgres; the spine's relational store)

```sql
CREATE TABLE generic_argument (
  ga_id            text NOT NULL,
  ga_version       text NOT NULL,
  profile          text NOT NULL CHECK (profile IN ('default','GPP')),
  warrant_type     text NOT NULL,
  body             jsonb NOT NULL,          -- full object, schema-validated on insert
  content_hash     bytea NOT NULL,
  ratified_at      timestamptz NOT NULL,
  ratifier_id      text NOT NULL,
  PRIMARY KEY (ga_id, ga_version),
  CHECK (profile <> 'GPP' OR warrant_type = 'guideline-rule')
);
-- immutability: REVOKE UPDATE, DELETE ON generic_argument FROM ALL;

CREATE TABLE actual_argument (
  arg_id           text PRIMARY KEY,        -- ULID
  patient_id       text NOT NULL,
  encounter_id     text NULL,
  ga_id            text NOT NULL,
  ga_version       text NOT NULL,
  verdict          text NOT NULL CHECK (verdict IN ('released','held','flagged')),
  claim_type       text NOT NULL,
  profile          text NOT NULL,
  prev_hash        bytea NULL,
  content_hash     bytea NOT NULL UNIQUE,
  supersedes       text NULL REFERENCES actual_argument(arg_id),
  evaluator_version text NOT NULL,
  version_stamp    text NOT NULL,
  body             jsonb NOT NULL,
  created_at       timestamptz NOT NULL DEFAULT now(),
  FOREIGN KEY (ga_id, ga_version) REFERENCES generic_argument(ga_id, ga_version)
);
CREATE INDEX ON actual_argument (patient_id, created_at DESC);
CREATE INDEX ON actual_argument (ga_id, ga_version);
CREATE INDEX ON actual_argument USING gin (body jsonb_path_ops);
-- append-only: REVOKE UPDATE, DELETE; INSERT granted to role spine_evaluator only.
-- hash-chain trigger: BEFORE INSERT verify prev_hash = (SELECT content_hash FROM actual_argument
--   WHERE patient_id = NEW.patient_id ORDER BY created_at DESC LIMIT 1) or NULL for genesis.

CREATE TABLE argument_defeater (
  arg_id text REFERENCES actual_argument(arg_id),
  finding_ref text NOT NULL,
  source text NOT NULL,
  defeats_element text NOT NULL,
  defeats_ref text NOT NULL,
  acknowledged_by text NULL,
  PRIMARY KEY (arg_id, finding_ref)
);
```

The `body` column is the canonical JSON; the scalar columns are query projections and must be derived from `body` on insert (trigger or application-side, with a CI test asserting equality).

### 4.2 Event stream

| Event | Payload | Emitted when |
| --- | --- | --- |
| `argument.released` | `arg_id`, `patient_id`, `claim_type`, `content_hash` | Evaluator commits a Released argument |
| `argument.held` | same | Verdict held (consumed by governance only, never by faces) |
| `argument.flagged` | same plus `fit` summary | Verdict flagged (clinician face renders via fit-judgment flow) |
| `argument.superseded` | `arg_id`, `supersedes` | Correction committed |
| `generic_argument.ratified` | `ga_id`, `ga_version`, `supersedes[]` | Knowledge-plane ratification |

Faces subscribe to `argument.released` and `argument.flagged` only. A subscription filter that admits `argument.held` to a face role is a conformance failure (§9 T-07).

### 4.3 FHIR R4 projection (read-only, derived, rebuildable)

| Argument element | FHIR resource.element | Mapping |
| --- | --- | --- |
| ActualArgument (released) | `GuidanceResponse` | one per released argument |
| `arg_id` | `GuidanceResponse.identifier` | system `urn:makoha:arg` |
| `warrant.ga_id@ga_version` | `GuidanceResponse.moduleCanonical` | `PlanDefinition/{ga_id}\|{ga_version}` |
| `evaluation.verdict` | `GuidanceResponse.status` | released→`success`; flagged→`data-required` (fit-judgment needed); held→not projected |
| `subject_ref`, `encounter_ref` | `subject`, `encounter` | direct |
| `created_at` | `occurrenceDateTime` | direct |
| `author` | `performer` | `Device/{evaluator_id}` |
| `grounds[i].resource_ref` | `reasonReference[i]` | Observation, Condition, DiagnosticReport, DocumentReference |
| `claim.content`, `claim.verbatim_fragment_refs` | `result` → `RequestGroup.action` | one action per claim; fragment refs as `action.documentation` |
| `evaluation.gate_results` | `evaluationMessage` → `OperationOutcome.issue[5]` | `issue.code = informational`, `issue.details.coding.code = gate name`, `issue.diagnostics = result` |
| `qualifier` | `GuidanceResponse.extension[makoha-qualifier]` | five-signal JSON verbatim; no FHIR core element carries typed uncertainty |
| `rebuttals[i]` | `DetectedIssue` | `implicated = [GuidanceResponse, defeated element ref]`; `evidence.detail = finding_ref`; `severity` from source map; `mitigation.action` set on acknowledgement |
| `pins`, `prev_hash`, `content_hash`, `supersedes` | `Provenance` | `target = GuidanceResponse`; `agent.who = Device/evaluator`; `entity[]` role `derivation` for draft, `source` for each Pin; `signature = content_hash`; a correction adds `entity.role = revision` pointing at the superseded |
| Reads of the argument by any face | `AuditEvent` | `entity.what = GuidanceResponse`, `agent.who = principal`, `purposeOfUse` |

Projection is materialised by an event consumer and can be dropped and rebuilt from `actual_argument` (SPINE-9). A FHIR search must never be the write path.

## 5. Register rendering contract

A renderer is a pure function `render(A: ActualArgument<Released|Flagged>, register) -> Rendering`. Three registers, one content-set. Implements CONTRACT-RRI-1 as shipped in the corpus.

### 5.1 Element map (published by every renderer)

Every renderer, including any LLM narration renderer, ships a machine-readable element map: for each output span, the stable key in `A` it carries. The RRI harness reads the map, never the prose.

| Element key | Weight-bearing attributes (must be unchanged) | Compression permitted |
| --- | --- | --- |
| `claim.content` + each `claim.verbatim_fragment_refs[i]` | none | wording, not fragment identity |
| `grounds[i].coded_finding` | `grounds[i].provenance`, `capture_context` | merge several grounds into one sentence |
| `warrant.ga_id@ga_version` | `warrant.applicability` | citation form |
| `backing[i].source` | `backing[i].tier` | list → count with drill-down |
| `qualifier` (whole) | every `Posterior.probability`, `Coverage.coverage`, `Membership.degree`+`term`, `Reliability.reported_degree`, `Fit.status`+`attributes[]` | plain-register words for numbers (PV-1), never omission |
| `rebuttals[i].content` | `rebuttals[i].source`, `defeats` | one clause per rebuttal minimum |
| `evaluation.evaluator_version` | each `gate_results[i].result`, `override_state`, `verdict` | collapsed strip with drill-down (CC-5) |

### 5.2 Register rules

| Register | Face | Vocabulary source | Hard rules |
| --- | --- | --- | --- |
| clinical | clinician | clinical codebook (FS-4) | Five signals render as five identities (HR-2, CV-1); membership never as probability (CV-2); envelope badge at claim weight (CV-3); full tree one interaction away (CS-3) |
| plain-language | patient | plain codebook (FS-4), ratified per language pack | No percentages, probabilities, μ values or scores (PV-1); fit-uncertainty and degree-uncertainty worded and styled distinctly (PV-2); renders only `Released` arguments after clinician sign-off (TR-3, PS-3); patient's own grounds may reflect immediately |
| compliance | auditor | compliance codebook; AF-3 state vocabulary | Argument pair rendered (GenericArgument at pinned version beside ActualArgument), departures localised to warrant node (AF-2); every fired rule, μ-vector, threshold and pin listed on demand (FA-1) |

### 5.3 Property test (CI, G-class, hard failure)

```
for A in release_fixtures:
  for (f1, f2) in [(clinician,patient),(clinician,auditor),(patient,auditor)]:
    c1 = content_set(render(A,f1), element_map(f1))
    c2 = content_set(render(A,f2), element_map(f2))
    verdict = {ADDED: c2-c1, REMOVED: c1-c2, REWEIGHTED: weight_diff(c1,c2)}
    assert verdict == {ADDED:[], REMOVED:[], REWEIGHTED:[]}
```

Also required: plain-register lint (PV-1 prohibited-token list over rendered output), clinical microcopy lint (CV-4: no confidence/probability vocabulary attached to membership or fit spans), bright-line test (no `Held` argument reachable by any renderer; no `Flagged` argument reachable by the plain renderer).

## 6. Pin set

`pins` is the 0.1.0 `VersionSet` unchanged: `version_stamp` plus nine roles, each `pinned{id, version, sha256}` or `unavailable{reason}` or `not_applicable{reason}`.

| Role | Required state by warrant\_type | What it pins |
| --- | --- | --- |
| `template` | pinned, all | GenericArgument `ga_id@ga_version` + `content_hash` |
| `terminology` | pinned, all | Terminology release id (e.g. SNOMED CT-AU release date, AMT release, LOINC version) |
| `library` | pinned, all | Evidence-library snapshot hash |
| `engine` | pinned for bayesian-likelihood, fuzzy-precondition; not\_applicable for guideline-rule | Ommatidium build id |
| `configuration` | as `engine` | Engine configuration hash |
| `model` | pinned for bayesian-likelihood; not\_applicable otherwise | Model weights hash and registry id (ME-6) |
| `codebook` | pinned when any Membership signal present | Codebook version per register |
| `membership_function` | pinned when any Membership signal present | FML artefact version (FX-1) |
| `envelope` | pinned, all | ApplicabilityEnvelope version (MS-1) |

`version_stamp` is a lockfile digest: `sha256` over the sorted `(role, id, version, sha256)` tuples of every pinned role. Replay (RG-4) resolves every pinned role from immutable stores, re-runs the evaluator, and asserts `content_hash` equality; any mismatch is a replay failure with the diverging element named.

Storage: pinned artefacts live in content-addressed object storage keyed by their sha256; the spine refuses to commit an `ActualArgument` whose pinned sha256 is not present (D constraint via a `pin_registry` table with FK).

## 7. API surface

All paths under the spine's standards API. Write path is a single internal endpoint bound to the evaluator's service identity. Every read is logged as `AuditEvent` with register and purpose.
